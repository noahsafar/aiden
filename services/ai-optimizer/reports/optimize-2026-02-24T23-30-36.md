### Edit 1: Strict deadline extraction rules
File: src-tauri/src/commands/ai.rs
Function: analyze_email_claude
Dimension(s): no_false_deadline, deadline_display
Reasoning: The model is hallucinating deadlines (e.g., "2026-02-27") from emails that contain dates for events or FYI references (Cases S1, S2, P4). We must enforce a stricter "Action Required" check to prevent extracting dates that are merely contextual.

Old:
- Deadline: Extract a deadline ONLY if the user personally must complete an action BY that date or face a consequence (missing out, late penalty, expiration). This includes payment due dates, warranty expirations, contract renewal deadlines, and registration closing dates. Use ISO format (YYYY-MM-DD). Set to null if no deadline applies.

New:
- Deadline: Extract a deadline ONLY if the user personally must complete an action BY that date.
  **STRICT EXTRACTION RULE:**
  1. Is there a specific Action verb? (Submit, Apply, Register, Pay, Reply, Sign, Renew).
  2. Is there a Cutoff constraint? ("By [date]", "Due [date]", "Before [date]", "End of day").
  If both are true, extract the date. If the date is just an event start time, appointment time, or "FYI" date, set deadline to null.
  VALID DEADLINE: "Submit report by Friday", "Apply before March 15".
  INVALID DEADLINE (Set to null): "Meeting on Tuesday", "Prescription ready for pickup on Feb 24", "Event happening at 5 PM".
  Use ISO format (YYYY-MM-DD). Set to null if no deadline applies.
